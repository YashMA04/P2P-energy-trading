# P2P Energy Community Control: What Was Built and Why

This document explains the two parts of the v2 capstone work: the learning
method that controls a 25-home energy community (Part A), and the 3D
stakeholder platform that lets anyone watch, configure and compare it (Part B).
Every number below is regenerated by a command listed in the last section.

## Summary

The examiner's verdict on v1 was that "MAPPO is very basic". v2 replaces it with
an oracle-guided Multi-Agent Transformer (MAT), trained by imitating an exact
optimiser (DAgger) and then fine-tuned with reinforcement learning, protected by
a provable safety layer, settled with a game-theoretic fair-share rule, and run
with a decentralised fallback for when communication fails.

| Method (reporting day, 3 seeds, battery-neutral) | Cost per day | Share of possible saving |
|---|---:|---:|
| Grid-only (no coordination) | €175.89 | 0% |
| v1 MAPPO, final checkpoint | €173.43 | 3% |
| v1 MAPPO, checkpoint picked on the test day | €151.27 | 32% |
| Rule controller with the v2 safety layer | €143.90 | 41% |
| Model-predictive control, 3-hour window | €135.93 | 52% |
| Oracle-guided MAPPO student | €116.06 | 78% |
| Oracle-guided MAT student (DAgger) | €113.84 | 80% |
| **MAT + RL fine-tuning (final)** | **€112.00** | **83%** |
| Exact optimum with perfect foresight (bound) | €98.74 | 100% |

Zero unserved energy and zero missed EV charging on every seed and every day
tested. With the hybrid fallback, the controller also stays safe in every
communication-outage scenario tested (€112–124/day against €144 for the rule
controller).

## Part A: The learning method

### A1. The problem

* 25 homes, each with everyday demand, 20 with rooftop solar, 15 with a home
  battery, and two electric cars each, on one day in 96 fifteen-minute steps.
* All homes share one feeder cable: 200 kW import and 125 kW export limits.
* Homes trade with each other in a uniform-price double auction each step;
  what is not traded goes to or from the grid at the home's tariff.
* Each home's controller sets five numbers per step: battery power, each car's
  charging or discharging, and the quantity and price of its market offer. The goal is the lowest total
  community cost while every car is charged by departure, nobody's demand is
  shed, and the feeder is never overloaded.

### A2. What was wrong with v1 (verified, then fixed)

* The safety layer that guarantees EV charging had three bugs: it made the whole
  setpoint firm instead of only the minimum, it required more energy than
  necessary, and it was off by one at the final step. v2 fixes all three.
* The linear-programming benchmark allowed buying from the grid to sell to
  peers (562 kWh of arbitrage) and discharging cars below their floor. v2 uses an
  exact mixed-integer model that matches the simulator.
* The reported v1 checkpoint was chosen on the test day itself. v2 selects only
  on separate validation days.

### A3. The final method, stage by stage

```
exact optimiser (MILP) ──labels──▶ DAgger imitation ──▶ MAT student ──▶ PPO fine-tuning
        │                                                                │ (kept only if it
        ▼                                                                ▼  wins on validation)
  optimum €98.74                                   safety layer + fair settlement + hybrid fallback
```

1. **Exact benchmark.** A mixed-integer program solves the whole day with perfect
   foresight, using the same physics as the simulator (tariffs per home, battery
   wear, cars' departure needs, a battery-neutral end of day). Its €98.74 is the
   best any controller could do and defines "share of possible saving".
2. **Safety layer.** Two shields correct any action before it reaches the
   simulator. The per-vehicle shield guarantees each car reaches its departure
   charge. The community shield plans every car's minimum charging as late as
   possible inside the feeder's remaining capacity, so the cars can never jointly
   overload the cable. Safety therefore never depends on what was learned.
3. **Privileged teacher.** The exact optimiser is solved on 96 perturbed training
   days. It sees the future, so it cannot be deployed, but it can teach.
4. **DAgger imitation.** The student drives the simulator; at the states the
   student actually visits, the optimiser is re-solved from that state and its
   decision becomes the label. Only solutions proven optimal are used. This beat
   plain behaviour cloning (€190–211/day) by correcting the student's own mistakes.
5. **Multi-Agent Transformer.** An encoder reads all 25 homes' observations;
   a decoder decides homes one at a time, each seeing the decisions already made
   (ordered by EV urgency). This lets homes coordinate within a step. The same
   pipeline also trains a decentralised MAPPO student that needs only its own
   home's data.
6. **RL fine-tuning.** Proximal policy optimisation continues from the DAgger
   model with a penalty for drifting away from it and a critic warm-up. The
   fine-tuned model replaces the DAgger model only if it is cheaper on the
   validation days. Result: seeds 0 and 2 improve (€116.20 → €114.33,
   €111.85 → €108.21); seed 1 keeps its DAgger model. Mean €113.84 → €112.00.
7. **Fair settlement.** Each home's share of the community saving comes from
   the duals of the optimal plan (an Owen allocation, verified to lie in the
   core). It is budget-balanced, and no home pays more than its grid-only bill
   whenever the community saves.
8. **Strategic robustness.** Bid shading and withholding were tested against the
   market; settling on metered energy rather than reported quantities removes the
   gain from misreporting.
9. **Hybrid execution.** MAT is a central controller, so it needs a working
   link to every home. The deployed configuration is:
   * every home reachable: MAT controls the community;
   * any home cut off: every home switches to its local MAPPO student (chosen on
     validation days, where switching everyone beat keeping MAT for the rest at
     every share tested, down to a single home);
   * a cut-off home limits its own import to 8 kW and the operator reserves that
     capacity, the same idea as Australia's default operating envelopes
     (CSIP-AUS). This makes the guarantee hold for any fallback behaviour,
     including an adversarial one.

### A4. Communication outages (reporting day, mean of 3 seeds)

| Scenario | Proposed hybrid | MAT, no fallback | Rule controller |
|---|---:|---:|---:|
| No outage | €112.00 | €112.00 | €143.90 |
| Every home cut off 17:00–21:00 | €112.43 | €127.33 | €143.90 |
| One home cut off all day | €117.32 | €122.77 | €143.91 |
| 30% of homes cut off all day | €118.61 | €155.49 | €143.90 |
| Operator down all day | €123.55 | €173.84 | €143.86 |

Unserved energy is zero in every cell. The safety envelope costs between €0 and
€7.49/day during long outages; that is the price of the guarantee.

### A5. What did not work (reported, not hidden)

* Behaviour cloning of the optimiser (€190–211/day) and a state-of-charge target
  action space (€363–369/day).
* The decoding-order ablation: random order performed as well as urgency order.
* RL fine-tuning on seed 1 (rejected on validation).
* Keeping MAT running for reachable homes during a partial outage: MAT is brittle
  to stale inputs, which is why the hybrid switches everyone.

### A6. Is this reinforcement learning?

Yes, in two places. DAgger is imitation learning inside a sequential decision
process, the MAPPO and MAT policies are multi-agent RL architectures, and the
final stage is on-policy PPO with a learned critic. The optimiser is a teacher
used only in training; the deployed policy is a neural network that acts in
milliseconds without seeing the future.

### A7. Limitations

* One day of data (with noisy variants); results are not seasonal.
* The 25-home study community is the only one trained on.
* Outages are simulated as loss of contact; delays, wrong data and a faulty
  operator are not modelled.

## Part B: The stakeholder platform

### B1. Purpose

A browser-based control room for people who will not read code: community
members, a network operator, examiners. It shows what the controller does,
what happens when communication fails, and what each home pays.

### B2. Two modes

* **Replay** (no Python needed): open `platform/index.html`, or the published
  web page. It plays recorded days of the study community for every controller
  and scenario.
* **Live**: `python platform/server.py`, then open `http://localhost:8765`. Each
  step is computed by the simulator as you watch. You can build your own
  community, define your own outage, cut the operator's link at any moment, and
  compare every controller.

### B3. What the 3D scene shows

| Element | Meaning |
|---|---|
| Light moving along the street cables | Power through that cable. Blue moves towards homes (import), gold moves back towards the transformer (export). Brightness, width and speed grow with the power. Where neighbours supply each other, their flows cancel and the trunk cable dims. |
| Ring around the transformer | Feeder load as a share of its limit (red above 90%). |
| Operator mast and thin arcs | The control link to each home; a light pulse travels along each live link. Cut-off links turn dim orange and the beacon flashes red. |
| Ground outline of each home | Who controls the home: blue central MAT, amber local fallback, violet rule controller. |
| Solar panels, battery column, cars | Panels glow with the home's real solar output; the battery level rises and falls; cars leave and return on the recorded schedule and show a ring while charging. |
| Sky | Time of day, from the simulated clock. |

Around the scene: four status tiles (saving against grid-only, feeder load,
who is in control, demand served), a timeline with the day's feeder curve and
outage periods, a household panel when a home is clicked, and end-of-day bills.

### B4. Simulation variants

| Controller | What it does |
|---|---|
| **MAT + MAPPO fallback (proposed)** | Central MAT; on any outage every home runs its local MAPPO student, cut-off homes inside the envelope. |
| MAT + MAPPO for cut-off homes only | MAT keeps the reachable homes on a stale picture of the others. |
| MAT + rule fallback | Cut-off homes fall back to the tariff rule. |
| MAT, no fallback | Cut-off homes repeat their last setpoint (a naive central system). |
| MAPPO everywhere | Fully decentralised; no central controller. |
| Rule controller | Charge when power is cheap, use storage when it is dear. |

Scenarios: normal day, evening outage (17:00–21:00), one home cut off all day,
30% of homes cut off all day, operator down all day, or a custom outage (every
home or a chosen share, between any two times).

### B5. Customising the community (live mode)

| Setting | Range | Effect |
|---|---|---|
| Number of homes | 4–60 | Homes are drawn from the 250-home dataset, keeping the mix of solar, battery and car owners. |
| Draw number | 0–9999 | Picks a different set of homes. |
| Import / export limit per home | 4–17 / 2–17 kW | The feeder limits scale with the number of homes; the import limit is also the outage envelope. |
| Solar per home | 0–15 kW peak | Rescales the home's solar; a home without solar gets the dataset's average solar shape. |
| Battery per home | 0–30 kWh | 0.5 C power, 95% efficiency, half full at start and end (dataset medians). |
| Cars per home | 0 up to the recorded number | Removed cars no longer drive or charge. |
| Demand per home | ×0.25 to ×3 | Multiplies everyday demand. |

The default settings reproduce the study community exactly (tested). On any
other community the trained controllers run unchanged and the safety layer
still holds, but their costs are a generalisation test: the page says so.

### B6. Compare and bills

**Compare** runs all six controllers on the same community and scenario and
ranks them by battery-neutral cost, with the saving against grid-only, peak
feeder load and unserved energy. **Watch** opens any of those runs in the 3D
view. **Bills** lists each home's grid-only bill, settled bill and saving.

The platform uses the seed-0 models, so its numbers differ slightly from the
3-seed means above (for example €114.33 rather than €112.00 for a normal day).

### B7. How it is built

* `src/platform/custom.py`: builds a community from a JSON specification and
  validates every field with a readable error.
* `src/platform/sim.py`: the six controllers, the outage scenarios, a
  step-by-step simulation generator, and the comparison.
* `src/platform/recorder.py`: one frame per step (feeder load, prices, costs,
  each home's mode, storage levels, net power and solar).
* `platform/server.py`: Python standard library only. `GET /api/health`,
  `GET /api/defaults`, `POST /api/session`, `GET /api/stream` (Server-Sent
  Events, one frame per step), `GET /api/control` (cut link, speed),
  `POST /api/compare`.
* `platform/index.html`: three.js scene and interface in one file;
  `platform/classic.html` is the 2D version with the same features (set-up, custom communities, compare, bills, cut link); it works without internet.
* `scripts/export_platform_data.py`: records every controller × scenario for
  replay mode.

## Testing

Development followed small build-then-test steps: each module got its tests
first, then the code, then a full-suite run before moving on.

| Test file | What it checks |
|---|---|
| `test_v2_custom.py` (17) | Default spec reproduces the study community exactly; sizes 4–40; overrides reach the simulator; invalid input is rejected with a message. |
| `test_v2_sim.py` (20) | Scenario parsing; the hybrid reproduces the reported €114.33; all six controllers are safe on a custom 10-home community with an outage; comparison ranking; a mid-day link cut. |
| `test_v2_platform.py` (14) | Model selection rule; degrade switch; replay data complete and budget-balanced; server endpoints, custom sessions, cable cut, comparison, clear 400 errors. |
| `test_v2_platform_ui.py` (5) | Real browser on the 3D and 2D pages: replay, compare and switch variants, bills; phone width without sideways scroll; live custom communities with a cut and a full comparison. |
| `test_v2_hybrid.py` (10) | Outage safety under an adversarial fallback; negative control without the envelope. |
| Earlier v2 and v1 suites | Optimiser, shields, teacher, DAgger, MAT, game theory, v1 reproduction. |

Run everything with `python -m pytest tests -q`: 131 tests pass. Without
Playwright the five browser tests skip themselves (126 passed, 5 skipped).
